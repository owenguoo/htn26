# SwarmSight iOS

Phones become tracked cameras. Each one reports its 6DoF pose in a shared venue
frame plus periodic JPEG frames to the orchestrator over WebSocket, and displays
commands sent back: a full-screen flash, a directional arrow, a sound, a haptic.

This repo is a drop-in replacement for the **pose source and frame source** of a
web prototype that already exists and works. It does not replace the
orchestrator, the dashboard, the feed wall or the join flow. Read `CLAUDE.md` for
the constraints and `PLAN.md` for the sequence.

## Layout

```
Packages/SwarmCore/       pure Swift; no ARKit, UIKit, SwiftUI, CoreMotion or CoreHaptics
SwarmSight/               the thin app target
  ARKitPoseProvider.swift the ONLY file that imports ARKit
Fixtures/                 recorded trajectories and venue.json
tools/fixture-gen/        generates the stand-in fixtures
tools/mock-orchestrator/  a stub server, so the phones have something to talk to
DEVICE_CHECKLIST.md       everything the tests cannot prove
```

About 95% of the logic is in `SwarmCore`, behind `PoseProvider`, so it builds and
tests in seconds with no simulator and no device. ARKit plugs into that one seam.

## Verifying

```
Scripts/verify.sh
```

which is exactly:

```
cd Packages/SwarmCore && swift test
xcodebuild -scheme SwarmSight -destination 'platform=iOS Simulator,name=iPhone 16' build
```

**Neither proves positioning works.** ARKit does not run in the Simulator, so no
line of positioning code in this repo has ever executed. `DEVICE_CHECKLIST.md`
is the part a human does, and it is not optional.

## Two things to know before touching anything

**The fixtures are synthetic.** `Fixtures/trajectory-*.json` were generated by
`tools/fixture-gen/generate_trajectories.py`, not recorded on a device. They set
`"synthetic": true` and say so in their `note`. They approximate ARKit's drift,
jitter and dropout characteristics; they do not reproduce them. Replace them with
a real two-minute recording (PLAN.md human task 2) and re-run the suite — any
assertion about the *character* of ARKit motion is fiction until then.

**`venue.json` is loaded at runtime, never compiled in.** Changing venue is a
tape measure and a text edit, not a rebuild. The app prefers a copy in its own
Documents directory over the bundled one, and `UIFileSharingEnabled` is set, so
on the day it is an AirDrop.

## Running against the stub orchestrator

```
python3 tools/mock-orchestrator/server.py --port 8765
```

It prints its LAN address; set that as the app's `orchestratorURL`. It has a
small console — `flash`, `arrow <x> <y> <z>`, `buzz`, `clear`, `rates <hz>` — for
poking a phone by hand. It is a stub: if it and the real orchestrator disagree,
the real one wins.

## Model weights

`vggt_omega_1b_512.pt` is ~4.6 GB and gitignored, along with `*.pt`,
`*.safetensors` and `checkpoints/`. Do not commit it: GitHub rejects files over
100 MB, a multi-gigabyte blob makes every clone painful even via LFS, and the
FAIR Noncommercial Research License makes redistribution a licensing question as
well as a git one. Reference it by path from config.
